    Session 5 · Classification: Who Is Poor?¶

    Last session we predicted (log) income per capita and learned to report an honest error with a pipeline and cross-validation.

    Today's question. A programme does not pay "a predicted income" — it decides yes or no: does this household get the subsidy? So we predict the class directly: is the household poor?

    What is new today: logistic regression as a predictor, the confusion matrix, precision and recall, the decision threshold, the ROC curve and AUC, stratified splits — and how to put categorical variables and missing values inside the pipeline (OneHotEncoder, SimpleImputer, ColumnTransformer).

    2. Logistic regression — the model you know from econometrics, used to predict¶

    In econometrics you used the logit to estimate effects. Here it is the same equation, $P(\text{poor}) = 1 / (1 + e^{-(\beta_0 + \beta_1 x_1 + \dots)})$, but we judge it by how well it predicts households it has never seen. Start with the three numeric variables from Session 4.

    3. The confusion matrix: two different mistakes¶

    predicted not poor predicted poor
    actually not poor true negative false positive — subsidy to a household that does not need it
    actually poor false negative — a poor household is left out true positive
    • Recall = of the poor households, what share do we reach? TP / (TP + FN)
    • Precision = of the households we select, what share are actually poor? TP / (TP + FP)

    4. Use all the information: categorical variables and missing values in the pipeline¶

    Most of what we know about a household is categorical (region, tenure, health insurance…). Models need numbers, so OneHotEncoder turns each category into a 0/1 column. Missing values need a rule, and the rule depends on what missing means:

    Column Why it is missing Rule
    head_weekly_hours the head does not work fill with 0 — not the median!
    head_job_type the head does not work its own category, "missing"
    schooling, education, insurance, overcrowding "doesn't know" (rare) median / own category

    ColumnTransformer applies a different mini-pipeline to each group of columns. Everything that is learned (medians, categories, scaling) is learned inside the pipeline — on training folds only.

    In [5]:
    Copied! 
    from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import OneHotEncoder

pre = ColumnTransformer([
    ("num", make_pipeline(SimpleImputer(strategy="median"), StandardScaler()), NUM),
    ("hours", make_pipeline(SimpleImputer(strategy="constant", fill_value=0), StandardScaler()), HOURS),
    ("cat", make_pipeline(SimpleImputer(strategy="constant", fill_value="missing"),
                          OneHotEncoder(handle_unknown="ignore")), CAT),
])
model = Pipeline([("pre", pre), ("clf", LogisticRegression(max_iter=3000))])
model.fit(X_train, y_train)
print(f"Accuracy, all variables: {accuracy_score(y_test, model.predict(X_test)):.3f}")

    5. The threshold is a policy decision¶

    .predict() says "poor" when the probability is above 0.5. Nothing says 0.5 is right. Lower the threshold and we reach more poor households (recall ↑) at the price of subsidising more households that are not poor (precision ↓).

    In [7]:
    Copied! 
    p_test = model.predict_proba(X_test)[:, 1]
rows = []
for t in [0.1, 0.15, 0.2, 0.3, 0.4, 0.5]:
    pr = (p_test >= t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_test, pr).ravel()
    rows.append({"threshold": t, "selected": tp + fp, "poor reached (TP)": tp, "poor missed (FN)": fn,
                 "non-poor subsidised (FP)": fp, "recall": tp / (tp + fn), "precision": tp / (tp + fp)})
pd.DataFrame(rows).round(3)

    Suppose leaving out a poor household is judged three times as costly as subsidising a household that is not poor. Then we pick the threshold that minimises 3·FN + 1·FP. (We do it on the test set here only to see the idea; exercise 2 does it properly, with cross-validated predictions on the training set.)

    In [8]:
    Copied! 
    ts = np.linspace(0.02, 0.9, 89)
cost = [3 * ((p_test < t) & (y_test == 1)).sum() + ((p_test >= t) & (y_test == 0)).sum() for t in ts]
best = ts[int(np.argmin(cost))]
plt.plot(ts, cost); plt.axvline(best, ls="--", c="red")
plt.xlabel("threshold"); plt.ylabel("total cost (3·FN + FP)")
plt.title(f"Cost-minimising threshold ≈ {best:.2f}");

    The cost ratio is not a statistical question. It is a value judgement that belongs to whoever runs the programme — your job is to make the trade-off visible.

    6. The ROC curve and AUC: the model across all thresholds¶

    The ROC curve plots recall (true positive rate) against the false positive rate for every threshold. The AUC summarises it: the probability that a random poor household gets a higher score than a random non-poor one. 0.5 is a coin; 1.0 is perfect.

    Poverty is defined by comparing income per capita with a poverty line. Adding income makes the model look excellent and makes it useless: the entire reason for a proxy means test is that income is not reliably observed. Same lesson as income_decile last session.

    9. Reading the model (carefully)¶

    Exponentiated coefficients are odds ratios, as in econometrics. But this model was built to predict: the coefficients describe associations among correlated variables, not causal effects.
